# 桌面 UI 设计与验证

界面以 Windows 11 设置应用的布局习惯为参考：浅灰或深灰底色、稳定的侧栏、白色或深色卡片、蓝色操作强调、清晰的字体层级和统一的间距。保持 WinForms 与已有控制层，所有界面绘制和布局均在本项目内实现，无第三方 UI 依赖。

## 页面和状态

| 区域 | 内容与交互 |
| --- | --- |
| 导航 | 概览、应用设置；窄窗口中改为顶部导航 |
| 电池概览 | 环形电量指示、真实电量、供电状态、设备当前模式、最后读取时间 |
| 模式卡片 | 普通、电池养护、快速；单选圆点和强调边框表示选择，独立的“当前使用”标记表示设备实际状态 |
| 应用模式 | 仅在存在可用、待应用的不同模式时启用；写入和验证完成后更新实际状态 |
| 夜间充电 | 独立的开启／关闭按钮；读取失败时按钮显示不可用，旁边展示原因；等待操作时禁用，操作后采用读回状态 |
| 应用设置 | 语言、登录自动启动、托盘行为、清理并退出 |
| 状态与诊断 | 日常反馈保持简洁；可展开复制详细错误，设备状态不可用时自动展开 |

电量每 30 秒从 Windows 读取，不读写设备的模式设置。未知电量显示“—”，不显示假定的电池健康、剩余时间或充电上限。充电模式与夜间充电通过已有的刷新和验证流程查询。启动时不应用任何充电设置。

刷新保留当前页面及滚动位置，读取失败也不会强制切换页面。更新控件状态时先把即将禁用控件的焦点移到可见导航，避免 Windows 自动选择其他内容控件并滚动到它；状态更新的同步布局期间临时保留滚动偏移，正常 Tab 导航仍可自动滚动。等待设备读取时用户继续滚动或切换页面，完成后保留新的位置。重复读取同一个设备错误不会重新展开用户收起的诊断；新的设备错误仍会展开详情。状态文字预留两行高度，减少临时读取提示改变页面高度。

默认内容区域为 1020 × 760 个 96 DPI 设计像素。侧栏宽 200，主体内边距 24，卡片内边距 20，卡片圆角 8，操作控件最小高 36。控件随 DPI 缩放；窄窗口中隐藏侧栏、展示顶部导航，并将模式卡片排成一列。内容区滚动，底部“收起到托盘”和“退出”始终保留在页面之外。

内容页按视口宽度测量，预留稳定的垂直滚动条空间，随后按文字换行后的高度向下排列。电池摘要、设置项和应用操作在空间不足时把右侧内容移到下一行；模式卡片在内容宽度不足 580 个设计像素时改为纵向排列。卡片测量和绘制使用相同的标题、说明和生效标记区域，完整预留底部标记与内边距。侧栏底部说明也按可用宽度换行。

窗口和布局容器使用双缓冲，批量更新时暂停整个控件树的布局；控件值不变时跳过重复重绘。模式卡片复用标题字体，并缓存有限数量的文字测量结果。卡片内部使用与表面一致的实色背景，减少透明控件向上递归请求背景绘制。系统外观通知合并处理，未变化的配色不重复应用；托盘运行时暂停电量界面刷新，恢复窗口时立即更新。设备状态和自动启动状态独立并行读取，驱动 I/O 与验证仍在后台执行。

自绘按钮、开关和模式卡片关闭基类的 `Opaque` 标志，每次重绘先填充背景，再绘制当前文字、图标和状态，避免旧文字、悬停和选择效果残留在缓冲区。文字绘制保留 Graphics 的裁切与平移，并限制在各自文字区域；矢量图标独立保存、裁切和恢复绘图状态。键盘焦点使用主题色轮廓，鼠标捕获丢失、控件禁用或隐藏时清除按压反馈。

## 原生窗口与可访问性

保留系统标题栏、拖动、窗口缩放、最大化和 Snap 操作。通过 DWM 设置 Windows 11 窗口圆角和明暗标题栏，参考 [微软圆角文档](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners) 和 [DWM 窗口属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。不支持的属性在旧系统上跳过。

界面使用 Segoe UI 和随 DPI 绘制的细线矢量图标。明暗配色跟随当前用户的 Windows 应用主题，高对比度模式改用系统颜色。文本控件、按钮、单选卡片和开关保留 WinForms 的原生语义、焦点与键盘操作；开关和语言控件有本地化的可访问名称，卡片描述中包含真实生效状态。

快捷键：F5 刷新、Alt+1 概览、Alt+2 设置。Tab 移动焦点，空格操作按钮和开关，方向键切换模式选择。选择模式不写入设备。

## 代码位置

- `MainForm.cs`：设备操作、实际状态读回、托盘、语言保存和退出流程。
- `MainForm.Layout.cs`：两页布局、响应式排布、状态展示、配色和快捷键。
- `FluentControls.cs`：圆角表面、按钮、单选模式卡片、开关和电量环。
- `FluentLayout.cs`：受宽度约束的纵向内容、响应式行和模式卡片、滚动视口，以及布局批量更新。
- `FluentDrawing.cs`：代码绘制的矢量图标和圆角路径。
- `FluentPalette.cs`：浅色和深色配色。
- `WindowsAppearance.cs`：读取系统外观和应用原生窗口属性。

## 验证

跨平台行为检查包含原有设备、启动任务和配置检查，以及双语资源的键与格式参数一致性、明暗配色的正文对比度：

```powershell
dotnet run --project tests/BatteryCharge.Checks/BatteryCharge.Checks.csproj -c Release
```

Windows 界面检查必须在 Windows 上执行。它打开实际的 `MainForm`，使用模拟设备和模拟启动注册服务，语言配置写入临时目录，不访问真实联想驱动或注册计划任务：

```powershell
dotnet run --project tests/BatteryCharge.UiChecks/BatteryCharge.UiChecks.csproj -c Release -- artifacts/ui
```

检查覆盖只读启动、待应用选择、模式命令序列、生效标记、夜间充电按钮、启动开关、语言切换保留待应用选择、窄窗口布局、窗口恢复和功能不可用时的诊断。夜间充电检查确认窄窗口和常规窗口均可滚动到完整按钮，开启和关闭采用设备读回状态，不可用时保留入口、展示原因并禁止写入。执行成功后生成中英文、明暗、概览、设置以及窄窗口和错误状态的 PNG，便于复核实际控件布局。截图来自控件绘制，原生标题栏和 DWM 合成效果仍需在桌面上查看。

布局回归检查在中英文下遍历 640、800、819、820、900、1020 个设计像素宽度，检查可见控件不重叠、不超出父容器，文本高度完整、页面无水平溢出、底部操作保留。另覆盖长说明与 125%、150%、200% 字体放大、诊断滚动可达性、换页滚动复位，以及重复布局不会导致滚动条循环。字体放大用于文字布局压力检查，不能替代真实显示器 DPI 测试。慢设备检查通过模拟阻塞驱动读取，确认导航和 Windows 消息循环仍可响应。这些新增检查已跨平台编译，仍需在 Windows 上执行才能确认结果。

重绘回归检查在明暗主题下复用同一个位图，依次改变按钮文字、悬停、按压、开关及模式选择，再与从空白背景绘制的最终状态逐像素比较。另验证四角背景没有黑点、文字与图标不越界，以及带平移和局部裁切的绘制只修改目标区域。这部分检查需要 Windows GDI，Linux 环境只能编译。

刷新回归检查在已滚动的概览和设置页点击具有焦点的刷新按钮，模拟阻塞读取与读取失败，确认开始和完成时均保留当前页和滚动位置，窗口尺寸与位置不变。另检查读取期间继续滚动后不会恢复到旧位置，以及重复设备错误不会重开已收起的详情。窄窗口检查使用实际可见的顶部导航。

GitHub Actions 的 Windows 作业已加入界面检查和截图产物上传。当前 Linux 环境能够编译主程序与界面检查项目、运行跨平台检查；没有运行 Windows 界面检查或实机驱动验证。

实机复核应包含 100%、125%、150%、200% 缩放，中文和英文，系统明暗及高对比度，键盘操作，以及不同缩放显示器之间的移动。发布沿用 `scripts/publish.ps1` 或 `scripts/publish.sh`。
